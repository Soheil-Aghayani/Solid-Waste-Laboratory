# Proposal: FT-IR and XRD as portal pages

**Status: proposal. No files have been moved.** Decisions that need you are in section 6; each has a recommended default.

## 1. Goal and non-goals

**Goal.** Two new portal pages, `ftir.html` and `xrd.html`, that look and behave like the other pages: same header, navigation and footer, same tokens and dark mode, the shared Persian helpers, and offline use through the existing service worker. The tools' results must not change.

**Non-goals.** No bundler, framework or rewrite of the science code. No change to the home tiles (they wait for the clay icons). No new features in the tools. No redesign of the portal's header.

## 2. What I found (measured)

| Topic | Finding | Consequence |
|---|---|---|
| Page generation | `scripts/build-pages.mjs` builds every top-level page from `index.html` plus a fragment in `pages/content/`. Nav is code (`renderPrimaryNav`, `renderMobileSectionNav`, `renderMobileDock`), not hand-written. | New pages are one page definition plus one fragment. |
| Nav duplication | `scripts/build-equipment-shells.mjs` repeats the primary nav list for the 28 equipment pages. | A new link must be added in two places today. I will move the list into one module used by both. |
| CSS collisions | Only 3 class names overlap (`brand`, `controls`, `selected`). No id clashes. But both tools style bare elements (`header`, `button`, `table`, `dialog`...), and the portal has a global `* { margin: 0; padding: 0 }` reset. | Tool CSS must be scoped under a wrapper class, and the margins the tools relied on must be restored inside it. |
| Dialogs | FT-IR appends its dialogs to `document.body`, outside any wrapper. | They need to be appended to the tool's root so scoped styles apply. |
| SheetJS | Two different copies, about 950 KB and 1 MB (335 KB and 254 KB gzipped), both loaded eagerly on every visit. | Keep one copy and load it only when someone imports an Excel file. |
| Size | FT-IR code 65 KB, XRD code 34 KB. XRD needs `references.json` (1.08 MB, 305 KB gzipped) to work at all. 62 CIF files (1.1 MB) are only fetched on click. | Small enough to skip minification. `references.json` must be precached for XRD to work offline. |
| Shared code | The two `fa.js` files duplicate the digit, number and message helpers. | One shared module, with each tool adding only its own tables. |
| Layout width | Portal container is 1280 px wide; FT-IR was designed for 1340. | Fits; I will verify. |

## 3. Proposed structure

```
ftir.html  xrd.html                  generated by build-pages.mjs, like rules.html
pages/content/ftir.html  xrd.html    page fragments (the tool markup, no header or footer)

tools/
  shared/
    fa.js                            digits, numbers, Jalali dates, LTR isolates, message translator
    vendor/xlsx.mjs  LICENSE         the one SheetJS copy, loaded on demand
  ftir/
    app.js  import.js  fa.js  report-fa.js
    science.js  processing.js  references.js  report.js        unchanged
    tool.css                         scoped under .tool-ftir
    *.test.js                        existing 4 test files plus fa.test.js
  xrd/
    app.js  workbook.js  fa.js
    science.js  references.json  library/{cif,manifest.json}   unchanged
    tool.css                         scoped under .tool-xrd
    scripts/build_library.py  requirements-library.txt          kept with the data they build
    *.test.js

scripts/site-nav.mjs                 the single list of pages, groups and nav items (new)
```

Flat page URLs (`ftir.html`, `xrd.html`) match every other portal page. Code lives under `tools/` so the root does not fill with tool files.

## 4. How it fits the portal

- **Page chrome.** The tools' own header, nav and footer are removed. The portal's header and footer are used. The tool keeps its visible title and a small "local processing" badge. The licence notices (CC BY-NC-SA for the reference data, Solar CC BY 4.0) move into a footer block inside the tool, so they stay on the page.
- **Header search.** Like the gallery page, tool pages use the header variant without the rules search box, because it would search portal text that is not on the page.
- **Navigation.** A third group, "ابزارهای تحلیل" (analysis tools), with FT-IR and XRD: two new links in the primary nav (and its mobile menu), a section nav on tool pages, and one new item in the mobile dock. Every one of the 34 generated pages gets the new links.
- **Styling.** Tool CSS is converted once by script: every selector gets the `.tool-ftir` or `.tool-xrd` prefix, `:root` becomes the wrapper, and the tool's own `header`, `main` and `footer` rules are dropped. Dark mode and the theme toggle already work through the shared tokens.
- **Modules.** Tool scripts stay ES modules, loaded with `type="module"`. They keep the `?v=` cache-busting convention.
- **Shared helpers.** `tools/shared/fa.js` holds the common functions. The tool-specific translation tables stay in each tool's `fa.js`.

## 5. Offline and caching

- **Precache** (first visit): `ftir.html`, `xrd.html`, the two tools' JS and CSS, and `references.json`. About 0.4 MB more to download, compressed.
- **Runtime cache** (already how the worker treats `?v=` files): SheetJS after the first Excel import, and each CIF file after it is downloaded.
- **Cache version and `?v=`** are bumped whenever tool files change, as for the rest of the portal.
- **Proof.** `npm run test:sw` already tests the worker logic with a mocked cache. I will extend it to assert the tool pages and `references.json` are precached. The real service worker cannot register in this preview pane, so the live offline flow stays untested here, as before.

## 7. Build order (each step is verified before the next)

1. **Import** both repos under `tools/` (per decision 1), then delete the standalone-only files (servers, duplicate token copies, `index.html`).
2. **Shared nav module.** Move the nav list into `scripts/site-nav.mjs` and use it in both generators. Run the generators on the *unchanged* nav and commit the result alone: they currently rewrite every page with whitespace-only differences, and I want the later nav change to show only real changes.
3. **Shared `fa.js`.** Extract the common helpers; both tools' Persian tests must still pass unchanged.
4. **One lazy SheetJS** for both tools.
5. **Scoped CSS and fragments**, and the generator support for tool pages (page-specific stylesheet and module script).
6. **Navigation, dock, section nav and service worker** updates.
7. **Verification** (below), then cleanup.

## 8. Acceptance (what "done" means)

- `ftir.html` and `xrd.html` load from the portal with no console errors and no failed requests, in light and dark mode, on desktop and at phone width, with no horizontal overflow.
- **Same results as the standalone tools:** XRD demo pattern ranks calcium oxide first at ۸۳٫۳; FT-IR demo gives the same peaks and assignments; Persian-digit input works; the Excel import dialog, exports (CSV with byte order mark, HTML report) and dialogs work.
- **Layout parity:** I compare key elements' sizes between the standalone tool and the portal page (the same method that caught the FT-IR styling regression) and explain any difference.
- The new links appear on **all 34 generated pages**, with the correct active state on the tool pages.
- All tests pass from the portal: FT-IR (21), XRD (24), the service-worker test, and `data:validate`.
- No global style of any existing portal page changes (checked by comparing the generated pages' diff against the nav change only).

## 9. Risks

- **Header crowding** with 8 links (decision 3).
- **Scoping bugs** in converted CSS (mitigated by the parity comparison).
- **Margin reset:** the portal's `*` reset removes spacing the tools took from browser defaults; I restore it inside the tool wrapper and check it in the parity test.
- **A shared version token** means a forgotten bump leaves old tool code cached (the same trap as the rest of the portal; the worker test and the stale-version check I added earlier cover pages but not these new files yet, so I will extend the check).
